# Project Context Report — template

Produced by `project-explorer` at the start of a development session.
Structured Markdown. Every non-obvious claim carries a file path (and line
number when useful) as evidence. No large source excerpts; no information
without practical value for the task.

```markdown
# Project Context Report

## 1. Project Overview

<!-- one short paragraph -->

## 2. Technology Stack

<!-- tools and versions relevant to the task -->

## 3. Repository Structure

<!-- workspaces and the directories that matter for this task -->

## 4. Application Architecture

<!-- layers and key modules of the affected application, with file paths -->

## 5. Coding Standards

<!-- conventions the task must follow; point to the governing document
     instead of copying it -->

## 6. Architectural Decisions and Constraints

<!-- ADRs and hard rules the task must not violate, with one-line reasons -->

## 7. Testing Strategy

<!-- test types, locations, and how to run them -->

## 8. Development and Validation Commands

<!-- exact commands that exist in the repository; never invented -->

## 9. Important Dependencies and Integration Points

<!-- services, infrastructure, and cross-app boundaries the task touches -->

## 10. Task-Relevant Context and Recommendations

<!-- where to start, what to watch out for, open risks -->
```
